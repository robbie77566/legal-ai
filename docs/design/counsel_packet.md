# The counsel packet

**Date:** 2026-10-19, revised 2026-10-23 after the UPL review · **Plan:** `docs/implementation/persona_rollout_plan.md` §3 (writ practitioner, PD appellate attorney), §5 E, January slice · **Trust posture:** `docs/business_case/attorney_offering_and_pricing.md` ("the verification posture should ship in the packet") · **Voice:** `docs/compliance/upl_review_2026-10-23.md` (P4, P5, P6, P8, P9; recommendations 6, 7, 8, 12).

A counsel matter's deliverable is a packet built for a brief, not a family letter. Part B comes first. The packet emits **record citations and doctrine categories, never case citations**, and — since the UPL review — it **describes and never speaks as counsel**: nothing in it is in the first person, nothing states what counsel has done, nothing says a bar "applies" or a step is "missed", and no case name is printed. A third-person tool statement on the first page says what the software did and did not do and that counsel decides every use of it.

Renderer: `packages/reports/counsel-packet.ts` (`renderCounselPacketPdf`, `counselPacketSections` — the same content as JSON, in packet order, for the web page and the tests). Statements and withheld templates: `packages/reports/disclosures.ts`. Routes: `apps/api/src/routes/counsel-packet.ts`; input built by `apps/api/src/services/counsel-packet.service.ts`. Template version `counsel-v1`, stamped on the cover beside the released report's own template (`AB-v2`). The family renderer lives in `packages/reports/family-report.ts`; the palette, footer and header both renderers share live in `pdf-helpers.ts`.

### The verified-against-record mark

The renderer never computes the mark. The api runs FR-7 (`verifyFindings`, the same call the family report makes at every render) and hands the renderer two lists, `findings` (verified) and `droppedFindings`; the mark is true for every finding in the first list because it is in that list, and the second list is printed under "Dropped at verification" and in the citation list as `dropped`. A finding cannot be marked verified by a flag, and a dropped one cannot vanish.

## Routes

Both at `/counsel/matters/:caseId/…`, under the matter routes' hooks: `counsel_surfaces` flag (404 when off), `PROFESSIONAL` with a live seat (403), organisation-scoped (another organisation's matter is 404). `409 { reason: 'NO_RELEASED_REPORT' }` before QA has released a report — the packet is built from the released report version the family route serves (`?version=` picks an earlier one).

- `GET …/packet.json` → `{ caseId, reportId, versionNo, templateVersion: 'counsel-v1', sections }`
- `GET …/packet.pdf` → the PDF, `attachment; filename="counsel-packet-<caseId>-v<n>.pdf"`

The only switch is `version=`. Unknown query parameters — including the former `clientLetter=1` and `wdtex=1` — are ignored, never a 400, so an old link still opens the packet without the withheld pages. Every fetch writes a `PACKET_DOWNLOAD` audit row with `{ format, versionNo, organisationId }` — ids only, never initials, a cause number or a county.

### The merits fact

`MatterCreateSchema` and `MatterPatchSchema` (`packages/case-lifecycle/matters.ts`) take `priorWritsDecidedOnMerits?: boolean | null`. It is stored on `Case.facts` (`CaseFactsSchema.priorWritsDecidedOnMerits`; no column, no migration), read back on `MatterView.priorWritsDecidedOnMerits` (null = not recorded), captured by the matter form's "Were the prior applications decided on the merits?" select (shown once a prior application is recorded; blank = "Not recorded yet"), and passed by `counsel-packet.service.ts` into `posture1107`. The matter page header prints *"Prior applications recorded: N · decided on the merits: not recorded / yes / no"* in place of the former "Posture: Subsequent application (§4)".

The ops case file (`GET /ops/cases/:id/file`) says which deliverable a case gets: `case.variant: 'family' | 'counsel'` (derived from the Matter row; no new column) and `case.matterVehicle`; the ops case page shows a COUNSEL PACKET chip. The matter page links to `packet.pdf`.

## Sealed attorney packet (2026-10-23, UPL review E2; counsel question 3)

The **family** product's attorney content — not the counsel-tier packet above. Finding E2 of `docs/compliance/upl_review_2026-10-23.md`: Part B, the preservation call, the harm standard, the vehicle and the develop steps were delivered to the family inline. Whether a family may receive Part B at all is counsel question 3; until counsel answers, the conservative default ships: the family report carries Part A, and the attorney content is one separate document the family downloads sealed and hands to licensed counsel, or shares by link.

- **Flag** `family_part_b` (default off; `20261023000038_family_part_b_flag`; `staff_console.md` §10). Read once per render in `loadVerifiedReport` (`apps/api/src/routes/intake.ts`), marked `// UPL review 2026-10-23: counsel decision pending (question 3)`. **Off:** `GET /cases/:id/report` omits `partBText`, `preserved`, `harmStandard`, `vehicle` and `develop` from every finding (`dependsOn` stays: the family can act on a missing record); the family PDF omits the per-finding "For an attorney" block, the labels line, "To develop", "For counsel — issues by priority" and "Investigation checklist" and prints one section **"For your lawyer"** (both languages, `FOR_YOUR_LAWYER_COPY`); the report page replaces the Part B folds and the priority section with the same card and two actions, *Download the attorney packet (sealed)* and *Share with a lawyer* (`apps/web/lib/content/attorney-packet.ts`, en/es, in the parity test). **On:** exactly the pre-split behaviour — `apps/api/tests/part-b-split.integration.test.ts` holds an inline snapshot of the payload shape taken before the change.
- **Renderer** `packages/reports/attorney-packet.ts`: `attorneyPacketSections(input)` → `cover` (the cover line *"For the attorney. - **Advice-language lint** (E3, recommendation 11): `apps/api/src/services/advice-lint.ts` — `lintAdvice(text, { audience: 'family' | 'counsel' })`. Prompt: the fixed system prompt gained *"You describe what the record contains. You never advise, never tell anyone what to file or when, never predict an outcome, and never address the family or the defendant directly."* and the v2 contract's Part A asks for a description of the cited page with no advice, instruction, prediction or "you should". The Strickland, preservation and severity instructions for Part B are unchanged (counsel reads it).
